# ChatGPT MCP import for Gourmet

Beat exposes a small, confirmation-first MCP server for importing meal records
from a ChatGPT conversation. The server does not and cannot pull a user's
ChatGPT account history. ChatGPT remains the orchestrator: it can use the
conversation context available to the user, extracts a structured candidate,
and sends only the candidate fields to Beat.

The existing Custom GPT Action remains supported. Use this MCP integration
when a regular ChatGPT conversation should be able to review its own context;
use the Action when a dedicated Custom GPT is preferred.

## Production endpoints

Set the non-secret production variable `BEAT_MCP_RESOURCE` to the exact
resource URL, normally:

```text
https://<beat-api-origin>/mcp
```

The MCP endpoint is `POST <BEAT_MCP_RESOURCE>`. Beat publishes protected
resource metadata at:

```text
https://<beat-api-origin>/.well-known/oauth-protected-resource/mcp
```

The root `/.well-known/oauth-protected-resource` alias is retained for clients
that do not implement the path-aware RFC 9728 lookup. The metadata points to
the Beat issuer (`BEAT_AUTH_ISSUER_URL`), whose discovery document advertises
Authorization Code + PKCE, token, revocation, and end-session endpoints.

`BEAT_MCP_RESOURCE` is not a secret and may be passed to SST as ordinary
Lambda configuration. The issuer, signing key, and Google credentials remain
in the protected runtime Secrets Manager JSON. The client allowlist is public
configuration passed through `BEAT_AUTH_CLIENTS_JSON`.

## OAuth client allowlist

Add a dedicated public client to the protected production Environment variable
`BEAT_AUTH_CLIENTS_JSON` (not to the runtime secret). The default deployment
uses a pre-registered `chatgpt-gourmet` client. Copy the exact callback URI
generated by the ChatGPT connector setup; the placeholder below is
intentionally not deployable:

```json
[
  {
    "client_id": "chatgpt-gourmet",
    "redirect_uris": [
      "https://chatgpt.com/connector/oauth/<callback_id>"
    ],
    "post_logout_redirect_uris": [
      "https://chatgpt.com/connector/oauth/<callback_id>"
    ],
    "resources": ["https://<beat-api-origin>/mcp"],
    "scopes": [
      "openid",
      "profile",
      "email",
      "offline_access",
      "gourmet:read",
      "gourmet:write"
    ]
  }
]
```

Replace both placeholders with the exact values shown by the connector
registration UI and use the same resource URL as `BEAT_MCP_RESOURCE`. Beat
rejects URI variations, unknown resource indicators, unsupported scopes, and
PKCE methods other than S256. Never add a wildcard, a query-string variant,
or a broad ChatGPT origin to the allowlist.

If the connector uses a Client ID Metadata Document (CIMD), allowlist its exact
`https://chatgpt.com/oauth/.../client.json` URL as `client_id` instead of
`chatgpt-gourmet`. Beat advertises CIMD only when that exact URL is present in
the allowlist; it does not fetch arbitrary client metadata or perform dynamic
client registration. This keeps the production client boundary explicit.

The OAuth flow is:

1. ChatGPT discovers the protected resource and starts Authorization Code +
   PKCE with `resource=https://<beat-api-origin>/mcp`.
2. Beat redirects to its configured Google SSO login. The authorization code is
   returned only to the exact ChatGPT callback with the original state.
3. ChatGPT exchanges the code with the S256 verifier. The access token has
   issuer `BEAT_AUTH_ISSUER_URL`, audience `https://<beat-api-origin>/mcp`,
   algorithm ES256, and a `scope` claim.
4. Beat validates the JWT signature, issuer, audience, expiry, administrator
   role, and requested Gourmet scope on every MCP request. Tokens are never
   placed in URLs, response metadata, or application logs.

Tool calls that arrive without a valid token return a JSON-RPC error result
with `_meta["mcp/www_authenticate"]` and the protected-resource metadata URL;
this is the signal ChatGPT uses to open its OAuth linking UI. Tool discovery
without a token also returns the standard HTTP `WWW-Authenticate` challenge.

If ChatGPT presents an `id_token_hint` on sign-out, Beat validates it before
identifying the client and applies the exact post-logout URI allowlist.

## Tool contract and confirmation boundary

The server exposes three tools:

| Tool | Scope | Writes data? | Purpose |
| --- | --- | --- | --- |
| `gourmet_get_context` | `gourmet:read` | No | Read recent published records for deduplication and preferences |
| `gourmet_preview_import` | `gourmet:read` | No | Validate and display extracted meal candidates |
| `gourmet_confirm_import` | `gourmet:write` | Yes | Save explicitly confirmed candidates as `draft` records |

The model should call `gourmet_preview_import`, show the complete candidate
records, and ask for explicit confirmation. It must call
`gourmet_confirm_import` only with `confirmed: true` after that confirmation.
Imported records are always `source: "chatgpt"` and `status: "draft"`; an
administrator reviews and publishes them from Beat `/admin/`. Each record is
idempotent, so retrying the same candidate does not create a duplicate.

The service accepts at most 24 records per call and bounds text and list sizes.
Logs contain only the imported count and authenticated subject, never meal
text, tokens, conversation content, or image bytes. The tool does not accept
image uploads; attach a photo later from the authenticated Beat administrator
screen.

## ChatGPT setup and verification

1. Deploy the API through the protected production GitHub Actions workflow with
   `BEAT_MCP_RESOURCE` and the exact client JSON set as protected production
   Environment variables.
2. In ChatGPT's connector/plugin settings, add the public HTTPS MCP URL and
   complete OAuth registration using the exact callback value supplied there.
3. Approve the Google SSO consent and verify that ChatGPT can list the three
   Gourmet tools.
4. Ask ChatGPT to summarize meal records visible in the current conversation.
   Confirm that it presents a preview before any write.
5. Confirm the preview, then check `/admin/` for a new draft. Publish it there
   only after reviewing the date, restaurant, rating, and summary.
6. Exercise the read-only connector with a token that lacks `gourmet:write`;
   `gourmet_confirm_import` must return a scope error.

This feature does not backfill all historical ChatGPT conversations in the
background. For a complete archive, use ChatGPT's official data export and a
separate reviewed import process; do not upload an unreviewed export directly
to a production write endpoint.
