# Beat 사이트 시각 개선 계획

작성일: 2026-09-27
검토 시작 기준: `main` / `b083dbb` (`origin/main`과 동일), 작업 트리 깨끗함

## 목표와 방향

Beat를 **기술 기록, 창작, 식사 기록이 공존하는 편집형 포트폴리오**로 읽히게 한다. 현재의 남색 배경, 코랄·시안·금색, 종이와 궤도 모티프는 유지하되, 화면마다 다른 장식 강도와 정보 밀도를 정리한다. 첫 화면에서는 “누가, 무엇을 만들고, 어디서 볼 수 있는가”가 즉시 보여야 한다. 모바일에서는 핵심 행동을 먼저 보여주고 설명은 짧게 둔다.

디자인 원칙은 다음 네 가지다.

1. **뚜렷한 주인공:** 홈의 이름/정체성, 대표 작업, 최신 콘텐츠 사이에 명확한 크기와 간격 차이를 둔다.
2. **콘텐츠별 개성, 공통된 문법:** 글은 읽기 쉬운 편집형, 소설은 몰입형, Gourmet는 사진 중심으로 두면서 제목·메타데이터·버튼·선·색의 규칙을 공유한다.
3. **읽기 우선:** 작은 보조 글씨와 반복 배지를 줄이고, 긴 한국어 제목의 줄바꿈과 본문 폭을 우선한다.
4. **절제된 반응:** 기존 움직임은 목적이 있는 곳에만 남기고 키보드, 터치, `prefers-reduced-motion`에서 동일하게 이해되도록 한다.

## 현재 상태에서 확인한 점

공개 사이트의 한국어 홈, 글 목록/상세, 소설 목록/읽기, Gourmet, 인물, 대표 프로젝트를 브라우저에서 확인했다. 모바일은 **390 × 844**, 데스크톱은 **1280 × 800** 뷰포트로 확인했다. 정적 코드도 대조했다.

| 우선순위 | 확인 결과 | 근거와 영향 |
| --- | --- | --- |
| P0 | 한국어 `Beat` 프로젝트 상세의 대표 이미지가 깨진다. | 공개 화면의 이미지 `naturalWidth`가 0이고 실제 요청 경로가 `/portfolio/ai-template-cover.png`다. 파일은 `apps/web/public/portfolio/`에 있고 Pages 배포에는 `/beat` 접두사가 필요하다. `apps/web/src/app/work/[slug]/page.tsx`의 `project.image` 사용을 확인한다. |
| P0 | 한국어 프로젝트 상세의 `프로젝트` 돌아가기 링크가 영어 홈으로 간다. | 공개 링크가 `/beat/#work`이고 코드의 `href="/#work"`가 원인이다. 한국어 홈의 `#work`로 연결한다. |
| P1 | 홈의 시각적 초점이 약하다. | 1280px 화면에서 4개 카드가 거의 같은 무게이고 `Arlequin × Lumen`은 11px 크기로 보인다. 대표 프로젝트와 최근 글도 비슷한 네모 패널이라 무엇부터 볼지 즉시 드러나지 않는다. |

| P2 | 섹션 간 시각 언어의 편차가 크다. | 소설 목록은 강한 타이포와 큰 작품 카드, 홈/글/프로젝트는 촘촘한 테두리 박스, Gourmet는 사진 타임라인이다. 같은 사이트임을 느끼게 하는 공통 제목·간격·버튼 체계가 부족하다. |
| P2 | 작품 탐색의 양이 크다. | 소설 목록에서 한 작품의 400개 회차가 한 목록에 이어진다. 첫 화·이어보기·최근 읽음은 살아 있으므로 이를 중심으로 회차 탐색을 단계화할 여지가 있다. |
| P1 | 전역 푸터의 보조 글씨가 테마에 따라 배경과 섞인다. | 데스크톱/모바일 라이트·다크 캡처에서 내부 페이지의 저작권·이메일이 거의 보이지 않는다. 기존 `--muted`는 보조 글자색이 아니라 표면색 토큰이다. |
| P1 | 글 목록이 한 화면 흐름에 너무 많은 글을 쌓는다. | 43개 글이 모두 이어져 모바일에서 선택 후 다음 행동까지 긴 스크롤이 필요하다. 주제/검색 필터와 결과 수는 유지하되 목록 이동 규칙을 소설 목록과 공유한다. |
| P2 | Gourmet 오류 화면이 로딩 레이아웃을 계속 차지한다. | API 실패 상태에서도 큰 빈 공간이 남고 다시 시도할 방법이 없다. 오류와 로딩의 접근성 상태 및 화면 높이를 나눈다. |

좋은 기반도 있다. 소설 읽기 화면은 본문 집중도가 높고, 인물 일러스트는 강한 고유 자산이다. Gourmet의 사진과 검색/필터도 실용적이다. 이를 새로운 공통 체계에 맞춰 다듬는다.

## 루나 구현 순서

각 단계를 작은 PR로 진행한다. 뒤 단계는 앞 단계의 디자인 규칙을 재사용한다.

### 1. 신뢰성 결함과 디자인 기준선 (P0)

- `siteAssetPath`를 사용해 프로젝트 이미지가 Pages의 `/beat` 경로에서 로드되게 한다. 이미지가 없는 경우에는 의도된 대체 시각 요소를 표시한다.
- 한국어 프로젝트 상세의 돌아가기 링크를 `localePath("ko")` 기반 `#work`로 연결한다.
- 기존 UI의 색상, 타이포, 간격, 표면, 버튼, 포커스 상태를 한 장의 간단한 기준표로 정리한다. 새 토큰은 `apps/web/src/app/styles.css`에서 적용하고 페이지별 덮어쓰기는 필요한 범위로 한정한다.
- 확인: 한국어 프로젝트 이미지 `complete && naturalWidth > 0`, 링크의 한국어 경로, 영어/일본어 프로젝트 링크와 자산 경로 회귀.

### 2. 홈의 첫인상과 이동 흐름 (P1)

- `apps/web/src/components/blog/home-index.tsx`와 홈 스타일에서 이름/정체성을 분명한 헤드라인으로 올리고, 대표 프로젝트를 첫 주요 사례로 보이게 한다. 현재 4개 목적지의 기능은 유지한다.
- 모바일에서는 4개 목적지 카드의 높이와 보조 문구를 줄여 첫 화면에서 대표 작업 또는 최신 콘텐츠의 시작이 보이게 한다. 반복되는 박스와 이중 테두리의 양을 줄인다.
- 홈의 최근 글은 제목과 날짜 중심으로 정리한다. 검토 상태는 확인 가능하면서도 제목보다 앞서지 않게 둔다. 소설 영역은 현재 3개 작품 구분을 유지한다.
- `apps/web/src/components/blog/app-shell.tsx`의 메뉴 발견성, 현재 위치 표시, 홈으로 돌아가는 경로를 모바일과 데스크톱에서 확인한다.
- 확인: 320/390/768/1280px에서 가로 넘침 없음, 3개 언어에서 제목 줄바꿈과 4개 목적지 링크 정확, 키보드 포커스가 보임.

### 3. 글·프로젝트의 편집형 화면 (P1)

- `localized-post-feed.tsx`의 검색/주제 필터는 유지하며, 목록에서 제목·주제·날짜의 순서를 분명히 한다. 긴 목록은 20개 단위로 나누고 회차 목록과 같은 페이지 이동 UI를 쓴다. 카드마다 반복되는 태그는 모바일에서 필요한 양만 보이게 한다. 검토 상태의 의미는 유지한다.
- 글 상세는 도입부, 본문, 출처, Beat 연결의 간격과 대비를 통일한다. 한국어 긴 제목과 영어/일본어 번역 제목을 각각 확인한다.
- 프로젝트 상세는 깨진 자산 수리 후 사례 이미지, 문제·작업·결과의 정보 계층을 명료하게 만든다. 실제 성과를 새로 지어내지 않고 현재 콘텐츠를 표현한다.
- 확인: 검색과 필터 동작, 320px 긴 제목, 출처 링크, 모든 프로젝트의 기본 목적지, 라이트/다크 대비.

### 4. 소설·Gourmet·인물의 마감 (P2)

- 소설 **읽기 본문과 저장된 읽기 설정은 유지**하고, 목록의 진입과 회차 탐색을 다듬는다. 400화 작품에서는 첫 화·이어보기·최근 읽음 및 회차 구간 이동을 쉽게 찾게 한다. 작품/세계관 관계를 바꾸지 않는다.
- Gourmet은 이미지 있는 카드와 `사진 없음` 카드의 높이·타이포·점수 표현을 맞춘다. 로딩 중에는 결과 레이아웃이 갑자기 바뀌지 않도록 안정된 자리 표시를 쓰고, 오류에서는 재시도 경로를 제공한다. 검색/필터/상세/지도 링크를 보존한다.
- 인물 페이지는 기존 Arlequin/Lumen 일러스트를 중심으로 제목, 소개, 역할 문장의 밀도를 다듬는다. 이미지의 초점과 크롭을 390px과 1280px에서 확인한다.
- 확인: 소설의 이어보기/회차/리더 테마, Gourmet 7개 기록 로드 및 필터, 인물 이미지 로드와 대체 텍스트.

## 공통 검증과 완료 기준

- 대표 경로: `/ko/`, `/ko/posts/`, 글 상세, `/ko/fiction/`, 회차 읽기, `/ko/gourmet/`, `/ko/characters/`, `/ko/work/beat-template/`; 영어와 일본어는 홈·목록·상세의 핵심 흐름을 함께 확인한다.
- 뷰포트: 320, 390, 768, 1280px. 라이트/다크, 키보드, 터치, 움직임 감소 설정에서 확인한다. 저장된 소설 읽기 테마의 첫 화면도 확인한다.
- 자동 점검: 관련 Playwright 흐름(`home-index`, `site-quality`, `gourmet-browser`, `fiction-reader`, `accessibility`)과 변경한 화면의 시각 기준. 자산 로드와 한국어 프로젝트 돌아가기 링크에 회귀 검증을 추가한다. 변경 범위의 typecheck/build도 실행한다.
- 시각 판정: 홈에서 정체성과 대표 작업이 먼저 보이고, 각 섹션의 첫 화면에서 다음 행동이 명확하며, 글/소설의 긴 제목이 좁은 화면에서도 편하게 읽힌다. 주요 이미지가 모두 로드되고 깨진 링크·가로 넘침·심각한 접근성 오류가 없다.
- 공개 후에는 GitHub Pages의 실제 URL에서 주요 경로, 자산, 모바일 화면을 다시 확인한다. 로컬 화면의 성공만으로 완료 처리하지 않는다.

## 구현 메모

- 이 계획은 디자인과 공개 웹 화면 범위다. 콘텐츠의 사실관계와 소설 본문은 현재 상태를 기준으로 둔다.
- `styles.css`에는 여러 시기의 홈/소설 규칙이 이어져 있다. 토큰과 섹션 규칙을 정리하면서 기존 리더의 테마·첫 화면 설정에 영향을 주지 않게 좁은 범위로 수정한다.
- 각 PR에는 변경 전후의 390px/1280px 캡처와 확인한 경로를 붙인다. 배포 후에는 앞서 정한 공개 경로를 확인한다.

## 전반 재검토에서 적용한 공통 규칙

- 본문/카드/입력/선택 상태/보조 글자/푸터는 테마 토큰을 사용해 라이트와 다크에서 같은 대비 관계를 유지한다. 사이트 메뉴와 언어·테마 조작도 같은 선·색 규칙을 따른다.
- 긴 글 목록과 회차 목록은 공통 페이지 이동 컨트롤을 사용한다. 필터 조건을 바꾸면 첫 페이지로 돌아간다.
- 로딩은 `aria-busy`와 자리 표시를 사용하고, 오류는 별도 안내와 재시도 동작을 제공한다.
- 추가 검토 경로는 홈, 글 목록/상세, 프로젝트, 인물, 소설 서가, 설정집, Gourmet이며, 한국어 화면을 390×844와 1280×900에서 라이트/다크로 비교했다. 이 검토용 로컬 캡처는 실제 사용자 데이터/API 응답을 대체하지 않는다.
