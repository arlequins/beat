## 재검토 결과 (2026-09-27)

첫 계획을 현재 코드와 공개 화면에 다시 대조했다. 시작 기준 이후 사이트 언어 지원과 디자인 시스템이 먼저 들어왔으므로, 아래 해결 항목은 열린 작업으로 세지 않고 지금 확인된 차이를 우선한다. 공개 화면은 GitHub Pages의 데스크톱 화면으로 한국어/일본어 홈과 일본어 프로젝트 상세를 확인했다. 모바일 전 경로와 테마 조합은 이 재검토에서 다시 캡처하지 않았으므로 완료로 간주하지 않는다.

- Gourmet은 로딩과 오류 상태를 구분하고 다시 시도하는 동작 및 접근성 상태를 제공한다.
- 공개 화면에서 Gourmet 7개 기록의 한국어 상세 문구를 수정한 상태를 확인했다. 다만 API 기록이 늘어날 때 번역 누락을 막는 CI 검사는 아직 열린 항목이다.

이 표는 재검토 시점의 기준 목록이다. 작업 브랜치에서 수행한 변경과 검증은 아래 진행 기록에 남기며, 배포 증거가 필요한 항목은 공개 확인 뒤에 닫는다.

## 진행 기록 (2026-09-27)

- 프로젝트 상세의 한국어·영어·일본어 하이라이트를 보완하고, 현지화 상세에 대표 이미지를 추가했다. 이미지 대체 텍스트는 각 언어의 프로젝트 제목을 사용한다.
- 홈 인물 카드의 한국어·영어·일본어 보조 문구를 제목과 다르게 바꿨다.
- 소설 본문과 작품 메타데이터는 한국어로 유지하고, 서가·회차 이동·뷰어 설정·접근성 이름·코멘트·설정집 탐색 UI를 언어별로 분리했다.
- 프로덕션 빌드는 정적 페이지 2,158개를 생성했다. 타입 검사, 변경 패키지 lint/typecheck, 런타임 단위 검사 19개, `actionlint`가 통과했다.
- 정적 빌드를 브라우저에서 열어 대표 경로 12개를 320/390/768/1280px로 확인했다. 확인 표본에서 문서 가로 넘침은 없었다. 320px 홈에서는 목적지 카드가 2×2로 보이고 대표 작업이 다음 섹션에 이어진다. 일본어 프로젝트 이미지의 실제 렌더링도 확인했다. 라이트/다크 테마 화면은 대표 페이지에서 확인했지만 모든 경로를 모든 테마로 캡처하지는 않았다.
- Gourmet 검사 실패 원인을 `경고가 하나라도 있으면 종료 코드 1`로 확인했다. 사진 없음과 사진 메타데이터 미확인 경고는 유지하고, 실제 오류만 CI 실패가 되도록 바꿨다. 경고가 남으면 단일 추적 이슈를 열고, 경고가 0이 된 뒤에만 복구 처리한다.

### 아직 남은 점

- 새 프로젝트나 Gourmet 기록의 번역 누락을 CI에서 차단하는 검사가 없다.
- 정적 HTML의 기본 `<html lang="en">`은 클라이언트 전 locale 보정이 필요하다.
- 12개 대표 경로의 4개 뷰포트는 확인했지만, 글 상세·모든 Gourmet 상세·설정집 각 경로의 테마별 캡처는 추가 검증이 필요하다.
- 변경은 아직 공개 배포 전이다. PR 체크와 공개 사이트의 최종 화면·워크플로 재실행으로 마감해야 한다.

## 목표와 방향

Beat를 **기술 기록, 창작, 식사 기록이 공존하는 편집형 포트폴리오**로 읽히게 한다. 현재의 남색 배경, 코랄·시안·금색, 종이와 궤도 모티프는 유지하되, 화면마다 다른 장식 강도와 정보 밀도를 정리한다. 첫 화면에서는 “누가, 무엇을 만들고, 어디서 볼 수 있는가”가 즉시 보여야 한다. 모바일에서는 핵심 행동을 먼저 보여주고 설명은 짧게 둔다.

디자인 원칙은 다음 네 가지다.

1. **뚜렷한 주인공:** 홈의 이름/정체성, 대표 작업, 최신 콘텐츠 사이에 명확한 크기와 간격 차이를 둔다.
2. **콘텐츠별 개성, 공통된 문법:** 글은 읽기 쉬운 편집형, 소설은 몰입형, Gourmet는 사진 중심으로 두면서 제목·메타데이터·버튼·선·색의 규칙을 공유한다.
3. **읽기 우선:** 작은 보조 글씨와 반복 배지를 줄이고, 긴 한국어 제목의 줄바꿈과 본문 폭을 우선한다.
4. **절제된 반응:** 기존 움직임은 목적이 있는 곳에만 남기고 키보드, 터치, `prefers-reduced-motion`에서 동일하게 이해되도록 한다.

## 이미 마련된 기반

사이트 공통 디자인 시스템, 프로젝트 자산 경로, 한국어 프로젝트 복귀 링크, 글 목록의 20개 단위 페이지 이동, Gourmet 오류/재시도 UI는 현재 구현에 반영되어 있다. 소설 리더의 본문·저장 설정, 인물 일러스트, Gourmet 검색/필터도 유지할 기반이다. 이 항목들을 다시 구현하는 대신 위 재검토에서 확인한 미완료 항목에 집중한다.

## 루나 구현 순서

이미 배포된 공통 디자인과 기능을 반복하지 않는다. 번역 품질과 화면 동등성을 먼저 바로잡고, 그 뒤에 반응형 시각 검증을 완료한다.

### 1. 프로젝트의 3개 언어 동등성 (P1)

- 한국어/일본어의 프로젝트 하이라이트를 현지화한다. 기술 제품명은 보존하고 동작과 결과를 설명하는 문구를 번역한다.
- 영어/일본어 상세에도 한국어 상세와 같은 프로젝트 이미지를 표시한다. 모든 페이지에서 `/beat` 배포 경로와 의미 있는 대체 텍스트를 확인한다.
- 홈의 한국어/일본어 인물 카드 설명은 제목을 되풀이하지 않도록 목적을 분명히 한다.
- 확인: 프로젝트 3개 × 3개 언어의 제목·설명·하이라이트·이미지·CTA 링크 비교.

### 2. 소설을 제외한 공통 인터페이스 현지화 (P1)

- 소설 본문과 세계관 문장은 번역하지 않는다. 서가, 회차 탐색, 읽기 설정, 접근성 이름, 설정집 탐색 UI는 한국어/영어/일본어로 표시한다.
- 언어 전환 뒤 작품 목록/상세/리더 내부 이동 경로가 현재 언어를 보존하는지 확인한다.
- 확인: 대표 작품 1개와 400화 작품에서 키보드·터치 이동, 이어보기, 설정 열기/닫기, 스크린리더 이름을 세 언어로 확인한다.

### 3. 번역 완전성 및 문서 언어 보호 (P2)

- 프로젝트와 Gourmet 번역 테이블의 누락 키, 예상 밖 키, 필수 필드 누락을 검사하는 CI 검증을 추가한다. 로케일 fallback이 사용자에게 원문 혼합으로 노출되지 않도록 한다.
- 정적 HTML 응답의 `html[lang]`이 `/ko`, 기본 영어 경로, `/ja`와 일치하도록 라우팅 구조를 정리한다. 클라이언트에서 바뀌기 전의 HTML도 검사한다.
- 확인: 새 샘플 항목을 번역에서 의도적으로 누락했을 때 검증이 실패하는지, 세 언어 응답의 lang/canonical/hreflang이 일치하는지 확인한다.

### 4. 공개 경로의 화면별 반응형 마감 (P1)

- 홈, 글 목록/상세, 프로젝트 목록/상세, 인물, 소설 UI, Gourmet에서 언어별 대표 경로를 선택한다. 320/390/768/1280px과 라이트/다크 조합으로 캡처한다.
- 제목 잘림, 겹침, 카드 높이 급변, 컨트롤 간격, 가로 스크롤, 이미지 크롭을 화면별로 기록하고 실제 문제만 고친다.
- 모바일 홈에서 4개 목적지 카드가 대표 작업·최근 글을 과도하게 아래로 미는지 판단하고, 한국어/일본어 중복 문구도 함께 정리한다.
- 확인: 변경 전후 캡처, 320px 가로 넘침 검사, 키보드 포커스, 검색/필터/언어 전환 회귀.

## 공통 검증과 완료 기준

- 대표 경로: `/ko/`, `/ko/posts/`, 글 상세, `/ko/fiction/`, 회차 읽기, `/ko/gourmet/`, `/ko/characters/`, `/ko/work/beat-template/`; 영어와 일본어는 홈·목록·상세의 핵심 흐름을 함께 확인한다.
- 뷰포트: 320, 390, 768, 1280px. 라이트/다크, 키보드, 터치, 움직임 감소 설정에서 확인한다. 저장된 소설 읽기 테마의 첫 화면도 확인한다.
- 자동 점검: 관련 Playwright 흐름(`home-index`, `site-quality`, `gourmet-browser`, `fiction-reader`, `accessibility`)과 변경한 화면의 시각 기준. 자산 로드와 한국어 프로젝트 돌아가기 링크에 회귀 검증을 추가한다. 변경 범위의 typecheck/build도 실행한다.
- 시각 판정: 홈에서 정체성과 대표 작업이 먼저 보이고, 각 섹션의 첫 화면에서 다음 행동이 명확하며, 글/소설의 긴 제목이 좁은 화면에서도 편하게 읽힌다. 주요 이미지가 모두 로드되고 깨진 링크·가로 넘침·심각한 접근성 오류가 없다.
- 공개 후에는 GitHub Pages의 실제 URL에서 주요 경로, 자산, 모바일 화면을 다시 확인한다. 로컬 화면의 성공만으로 완료 처리하지 않는다.

## 구현 메모

- 이 계획은 디자인과 공개 웹 화면 범위다. 콘텐츠의 사실관계와 소설 본문은 현재 상태를 기준으로 둔다.
- `styles.css`에는 여러 시기의 홈/소설 규칙이 이어져 있다. 토큰과 섹션 규칙을 정리하면서 기존 리더의 테마·첫 화면 설정에 영향을 주지 않게 좁은 범위로 수정한다.
- 각 PR에는 변경 전후의 390px/1280px 캡처와 확인한 경로를 붙인다. 배포 후에는 앞서 정한 공개 경로를 확인한다.

## 전반 재검토에서 적용한 공통 규칙

- 본문/카드/입력/선택 상태/보조 글자/푸터는 테마 토큰을 사용해 라이트와 다크에서 같은 대비 관계를 유지한다. 사이트 메뉴와 언어·테마 조작도 같은 선·색 규칙을 따른다.
- 긴 글 목록과 회차 목록은 공통 페이지 이동 컨트롤을 사용한다. 필터 조건을 바꾸면 첫 페이지로 돌아간다.
- 로딩은 `aria-busy`와 자리 표시를 사용하고, 오류는 별도 안내와 재시도 동작을 제공한다.
- 추가 검토 경로는 홈, 글 목록/상세, 프로젝트, 인물, 소설 서가, 설정집, Gourmet이며, 한국어 화면을 390×844와 1280×900에서 라이트/다크로 비교했다. 이 검토용 로컬 캡처는 실제 사용자 데이터/API 응답을 대체하지 않는다.
