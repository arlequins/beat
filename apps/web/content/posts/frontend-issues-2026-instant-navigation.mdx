## 화면을 빨리 보여줘도 모든 데이터를 캐시할 필요는 없다

Next.js 16.3은 화면 전환을 빠르게 보이도록 Stream·Cache·Block을 선택하고 일부 데이터를 미리 가져오는 기능을 소개했습니다. 사용자는 SPA처럼 빠르게 이동하지만, 개발자는 공통 화면 틀은 재사용할지, 데이터는 새로 받아올지 정해야 합니다.

## 캐시 범위도 보안 기준이다

사용자별 데이터나 권한이 필요한 화면까지 넓게 캐시하면 보안 문제가 생길 수 있습니다. 반대로 모든 화면을 Block으로 처리하면 새 기능의 이점이 사라집니다. 경로와 쿠키, 캐시 태그, 재검증 시간을 한곳에서 함께 관리해야 합니다.

## 검증할 지표

같은 계정으로 첫 화면과 다시 방문했을 때의 TTFB, INP, 데이터 최신성을 비교합니다. 뒤로 가기를 누르거나 느린 모바일 네트워크를 사용할 때 오래된 화면이 나타나지 않는지 확인하고, 캐시 갱신 실패를 로그에서 추적할 수 있게 합니다.
