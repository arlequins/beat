> Lumen이 리서치와 초안을 도왔습니다. 이 글은 Arlequin의 최종 검토 전인 공개 미확정본이며, 최종 판단은 Arlequin에게 있습니다.

10월 13일 기준, 지난 브리핑 이후인 10월 6~13일에 확인한 공식 자료를 모았습니다. 이번 회차는 화면을 더 잘 표현하는 브라우저 기능 두 가지와 런타임 패치 한 가지를 다룹니다. 아래의 도입 제안은 원문의 보장 사항이 아니라 Lumen의 개발자 관점 해석입니다.

## 1. JPEG XL: 새 포맷을 추가하되 실제 이미지로 비교하기

Chrome 팀은 10월 6일 Chrome 155부터 JPEG XL 디코딩을 지원한다고 발표했습니다. 원문은 고품질 사진, 무손실 압축, 점진적 디코딩에 주목하며 AVIF와 JPEG XL을 함께 시험하라고 권합니다. 디코더는 Rust 구현인 `jxl-rs`를 사용합니다. 이는 Chrome의 지원 발표이지 모든 브라우저에서 같은 결과를 보장한다는 뜻은 아닙니다.

개발팀의 다음 행동은 이미지 파이프라인을 한꺼번에 바꾸는 대신 대표 사진으로 비교표를 만드는 것입니다. 같은 시각적 품질에서 파일 크기, 모바일 디코딩 시간, 화면에 유용한 이미지가 나타나는 시점까지 측정하세요. 점진적 로딩이 중요한 상세 사진부터 시험하고, 기존 형식의 대체 이미지와 캐시 정책을 함께 검증하는 편을 제안합니다. 용량만 줄었는데 표시가 늦어지는 경우도 평가에서 걸러야 합니다.

출처: [Chrome for Developers — Shipping JPEG XL in Chrome](https://developer.chrome.com/blog/jpeg-xl-in-chrome)

## 2. WebGPU: 버전 번호보다 필요한 기능을 확인하기

10월 7일 갱신된 Chrome 155~156 WebGPU 자료에는 `fragment_depth` WGSL 확장과 `texture-compression-unaligned` 기능이 소개됐습니다. 전자는 출력 깊이의 관계를 명시해 early-Z 최적화를 적용할 수 있게 하고, 후자는 압축 텍스처의 크기가 블록 크기의 정수 배수가 아니어도 되도록 합니다. 원문은 각각 언어 기능 집합과 어댑터 기능 집합을 확인하는 예제를 제공합니다.

3D 뷰어나 GPU 처리 앱에서는 브라우저 이름만으로 빠른 경로를 선택하지 말고, 필요한 기능의 존재를 확인한 뒤 해당 경로를 요청하도록 설계하세요. 미지원 장치에는 기존 셰이더와 패딩된 텍스처 경로를 유지하는 방식을 제안합니다. 지원·미지원 환경에서 같은 장면의 시각적 결과와 GPU 시간을 비교하고, 성능 개선이 확인된 경로부터 활성화합니다. API가 있다는 사실과 사용자의 장치가 특정 확장을 제공한다는 사실은 별도로 확인해야 합니다.

출처: [Chrome for Developers — What's New in WebGPU, Chrome 155–156](https://developer.chrome.com/blog/new-in-webgpu-155-156)

## 3. Node.js 26.11.1: 패치의 변경 범위를 읽고 승격하기

Node.js는 10월 7일 26.11.1을 Current 릴리스로 공개했습니다. 공개된 커밋 목록은 문서 빌드·도구 변경을 되돌리는 세 항목입니다. 이번 릴리스를 LTS 전환이나 보안 패치로 소개할 근거는 이 변경 목록에 없습니다.

이미 26.x를 평가하는 팀이라면 26.11.0과의 차이를 확인하고, 새 버전의 설치·문서 접근·기존 테스트를 묶어 검증하세요. 운영에서 다른 지원 버전을 쓰는 팀은 이 패치 번호만으로 메이저 업그레이드를 결정할 필요가 없습니다. 개발 환경, CI 이미지, 배포 런타임이 같은 버전을 쓰는지 먼저 확인하고, 승격은 애플리케이션 테스트와 의존성 호환성 결과를 근거로 결정하는 편을 제안합니다.

출처: [Node.js — 26.11.1 Current 릴리스 노트](https://nodejs.org/en/blog/release/v26.11.1)

## 이번 주에 남길 결과물

이미지 비교표 한 장, WebGPU 기능별 대체 경로, 런타임 승격 기록을 남겨 보세요. 새 기능을 켰다는 사실보다 어떤 환경에서 이득이 있었고 어디에서 기존 동작을 유지했는지가 다음 배포의 판단 근거가 됩니다.
