> 이 패치노트는 Lumen이 현재 코드와 대화를 바탕으로 작성한 공개 미확정본입니다. Arlequin의 검토에 따라 표현과 우선순위가 달라질 수 있습니다.

## 이번 릴리스의 목표

인증·API·데이터베이스·관리 화면을 포함하던 범용 템플릿을 **GitHub 작업과 커리어의 맥락을 보여주는 개인 포트폴리오**로 전환했습니다. 처음부터 모든 운영 기능을 유지하기보다, 지금 필요한 공개 사이트와 글 작성 흐름에 집중했습니다.

## 1. 배포 구조를 정적 포트폴리오에 맞춤

- 웹은 정적 Next.js 출력으로 구성했습니다.
- Vercel에서 `apps/web`을 기준으로 배포할 수 있게 설정했습니다.
- 현재 포트폴리오 공개에는 Neon, API 서버, 인증 제공자가 필요하지 않습니다.
- 나중에 브라우저 CMS나 로그인 기능이 필요할 때 API와 데이터베이스를 다시 연결할 수 있습니다.

## 2. 프로젝트를 사례 연구로 전환

- 홈 화면에 GitHub 중심의 프로젝트 카드를 배치했습니다.
- 프로젝트마다 문제, 맡은 역할, 주요 구현, 결과를 설명하는 상세 화면을 만들었습니다.
- GitHub 메타데이터를 가져오지 못해도 로컬 설명으로 화면이 유지됩니다.
- 템플릿 자체, AI 협업 개발 흐름, 포트폴리오 콘텐츠 시스템을 첫 사례로 등록했습니다.

## 3. MDX 블로그와 세 개의 카테고리

글은 저장소 안의 MDX 파일로 관리하고 정적 페이지로 생성합니다.

- **주간 IT 브리핑** — 한 주의 주요 이슈와 다음 행동을 정리합니다.
- **테크 딥다이브** — 특정 기술과 설계 선택을 깊게 다룹니다.
- **프롬프트 & 패치로그** — Arlequin과 Lumen의 대화와 제작 변경을 공개합니다.

Studio Log 안에서는 `Prompt Log`와 `Patch Notes` 태그로 기록 형식을 구분합니다.

## 4. 공개 미확정본 상태 추가

모든 글은 다음 두 상태 중 하나를 갖습니다.

- `unreviewed` — 공개되어 읽을 수 있지만 상단에 미확정 안내가 표시됩니다.
- `reviewed` — Arlequin이 최종 검토한 글이며 미확정 안내가 사라집니다.

AI가 작성했다는 사실을 작은 각주로 숨기지 않고, 독자가 글의 상태를 읽기 전에 알 수 있도록 본문 상단에 배치했습니다.

## 5. Arlequin × Lumen 디자인 시스템

기존의 일반적인 개발자 포트폴리오 화면을 두 협업자의 서사를 중심으로 전면 수정했습니다.

- **Arlequin** — 코랄, 다이아몬드, 비대칭, 무대
- **Lumen** — 시안, 골드 광원, 궤도, 여백
- **공통 기반** — 미드나이트 네이비, 딥 플럼, 웜 아이보리

헤더의 결합 마크, 홈의 다이아몬드 궤도, 프로젝트 카드, 글 목록, 글 상세와 푸터가 같은 색과 형태를 공유합니다. 링크 공유 화면을 위한 전용 소셜 이미지도 제작했습니다.

## 6. 주간 브리핑 자동 작성

매주 월요일 오전에 Lumen이 다음 작업을 수행하도록 구성했습니다.

1. 신뢰할 수 있는 원문과 공식 자료에서 이번 주 IT 이슈를 확인합니다.
2. 세 개 안팎의 이슈를 개발자의 맥락과 다음 행동으로 정리합니다.
3. 출처 링크와 `reviewStatus: unreviewed`를 포함한 새 글을 만듭니다.
4. 타입 검사와 정적 빌드를 통과한 글만 GitHub에 올립니다.
5. GitHub와 연결된 Vercel이 새 커밋을 배포합니다.

자동 작업은 새로 만든 주간 글만 다루며, 작업 중인 다른 파일을 함께 커밋하지 않도록 제한했습니다.

## 7. 검증 결과

- TypeScript 타입 검사 통과
- Next.js 프로덕션 빌드 통과
- 홈, 글 목록, 다섯 개의 기존 글, 세 개의 프로젝트 상세 페이지 정적 생성 확인
- 정적 배포에서 데이터베이스와 인증 환경변수가 필요하지 않도록 정리

## 아직 남은 것

- 실제 이메일·LinkedIn·배포 도메인으로 자리표시자를 교체해야 합니다.
- Arlequin이 현재 공개 미확정 글을 읽고 `reviewed` 상태로 전환해야 합니다.
- 실제 GitHub 프로젝트의 수치와 결과를 보강할수록 포트폴리오의 설득력이 높아집니다.

다음 패치노트부터는 변경 이유, 사용자에게 보이는 차이, 검증 결과, 남은 제약을 같은 순서로 기록합니다.
