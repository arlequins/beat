> 2026-09-13 특별기획 · 공식 자료를 바탕으로 한 기술 해설

네트워크가 끊겨도 메모를 저장할 수 있으면 안심이 된다. 하지만 브라우저의 사이트 데이터를 지우거나 기기를 바꾼 뒤에도 기록을 복구할 수 있을까. 이 글에서는 로컬 저장의 장점과 함께 사용자가 알아야 할 점을 살펴본다.

## 브라우저 안의 데이터베이스가 주는 것

SQLite의 WebAssembly 문서는 OPFS에 데이터를 저장하는 여러 가상 파일 시스템(VFS)을 소개한다. 구현마다 성능과 여러 탭에서 동시에 사용하는 방법이 다르다. WebKit은 OPFS를 웹사이트 출처에 속한 파일 저장 공간으로 설명한다. 사용자가 일반 파일을 자신의 폴더에 저장하는 것과는 다르다.

이 차이는 화면의 문구에도 영향을 준다. 로컬 트랜잭션이 완료됐을 때 표시하는 저장 완료와, 다른 기기로 복사까지 끝났다는 동기화 완료는 분리하는 편이 좋다. 둘을 같은 체크 표시로 표현하면 사용자는 실제보다 강한 보장을 기대하게 된다.

## 동기화는 데이터베이스 밖의 설계다

여행 중 식사 기록을 남기는 앱을 생각해 보자. 휴대전화에서는 별점을 바꾸고 노트북에서는 같은 기록의 메모를 수정했다. 인터넷 연결이 복구된 뒤 어떤 값을 남길지는 로컬 SQL만으로 결정할 수 없다. 어떤 단위로 수정 사항을 합칠지, 충돌을 어떻게 처리할지, 삭제를 어떤 의미로 볼지도 따로 정해야 한다.

작은 서비스라면 처음부터 자동 병합을 약속할 필요가 없다. 서버 버전과 로컬 버전이 다른 항목을 보여주고 사람이 고르게 하는 방식도 출발점이 된다. 중요한 것은 마지막 응답을 무조건 덮어쓰는 일이 제품의 숨겨진 규칙이 되지 않는 것이다.

## 내보내기부터 복구를 시험한다

저장 기능을 만들 때는 데이터를 내보내고 다시 가져오는 기능도 함께 마련하는 편이 좋다. 파일이 다운로드됐는지만 확인하지 말고 새 브라우저 환경에서 내용과 날짜, 첨부 파일이 제대로 복구되는지 시험해야 한다. 사진을 저장했다면 사진은 빠지고 메타데이터만 복구되는 상황도 확인한다.

오프라인에서 새 기록 만들기, 두 탭에서 같은 기록 수정하기, 저장 실패, 사이트 데이터 삭제 후 복원을 테스트한다. 로컬 우선의 장점은 서버를 없애는 데 그치지 않는다. 연결이 끊겨도 작업을 이어가고 데이터가 어디에 저장되며 어떻게 복구되는지 사용자에게 설명할 수 있어야 한다.
