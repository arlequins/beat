## 보안 패치가 예외 작업이 아니게 되다

Next.js는 2026년부터 보안 패치와 사전 공지를 더 정기적으로 제공하는 절차를 소개했습니다. 운영팀은 기능 출시만 기다리지 말고, 현재 지원 중인 버전 계열을 계속 확인해야 합니다.

## 버전 숫자보다 산출물

`package.json`의 버전만 올려서는 충분하지 않습니다. 잠금 파일(lockfile), Docker 이미지, Lambda 실행 파일 묶음, CDN 캐시와 소스 맵도 같은 패치 버전을 가리키는지 확인해야 합니다. 실제 주소에 요청을 보내 헤더와 RSC 응답, 정적 자산을 스모크 테스트하는 이유입니다.

## 작게 자동화하기

Dependabot이나 Renovate가 만든 변경에 보안 라벨을 붙이고, 테스트가 끝난 뒤 정해진 승인 절차를 거쳐 배포합니다. 문제가 생겼을 때 이전 빌드로 돌아갈 수 있도록 배포 파일과 데이터베이스 마이그레이션도 분리해 두는 편이 안전합니다.
