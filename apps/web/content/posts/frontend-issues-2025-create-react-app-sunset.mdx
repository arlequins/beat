## “React를 시작한다”와 “Create React App을 쓴다”는 달라졌다

React 팀은 2025년 2월 새 애플리케이션에는 Create React App을 쓰지 말라고 권고했습니다. React의 시대가 끝났다는 뜻은 아닙니다. 앱의 화면 구성과 라우팅, 배포를 프레임워크나 빌드 도구가 더 잘 지원할 수 있다는 판단입니다.

## 선택 기준을 도구 이름에서 운영 경계로 옮기기

프레임워크를 고를 때는 SSR 여부만 보지 않습니다. 정적 export가 필요한지, 서버 함수가 어디에서 실행되는지, 캐시 무효화와 관측성을 누가 소유하는지까지 적어야 합니다. 작은 사이트라면 Vite와 정적 호스팅이 충분하고, 데이터·라우팅·서버 컴포넌트가 필요하면 Next.js나 다른 프레임워크가 더 적합할 수 있습니다.

## 다음 행동

기존 CRA 앱을 곧바로 다시 만들기보다 먼저 빌드 과정을 문서화하고 테스트, 환경 변수, 배포 파일을 점검합니다. 새 앱을 시작할 때는 “React 템플릿”을 고르는 데 그치지 말고, 어떤 서버 기능과 배포 환경이 필요한지부터 정하는 편이 안전합니다.
