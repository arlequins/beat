이번 주 소식은 강력한 도구를 제품 안에서 안전하게 다루는 방법으로 이어집니다. 에이전트에는 승인과 감사 기록이 필요하고, 데스크톱 앱은 실행 아키텍처의 전환을 준비해야 합니다. 운영 도구에서는 익숙하고 편리한 인터페이스가 사용자 권한까지 넓히지 않도록 주의해야 합니다.

## 1. GPT-6 Astra: 모델을 바꿀 때 도구 권한도 확인한다

OpenAI는 9월 3일 GPT-6 Astra를 공개하며, 도구를 사용할 수 있는 배포에 모니터링을 적용하고 고위험 사이버 역량에 맞춘 보호를 강화했다고 설명했습니다. API 모델 문서는 `gpt-6-astra`가 복잡한 추론·코딩·컴퓨터 사용을 위한 모델이며 웹 검색, 파일 검색, 컴퓨터 사용, MCP 등을 지원한다고 안내합니다. 즉, 모델을 바꾸는 일은 응답 품질만의 변경이 아니라 에이전트가 어떤 외부 시스템을 읽고 쓰는지 다시 확인하는 변경입니다.

모델을 교체하는 변경에는 새 모델이 사용할 도구와 권한 목록도 포함합니다. 읽기와 쓰기, 외부 전송 권한을 나누고 결제나 삭제, 배포처럼 되돌리기 어려운 작업은 사람이 확인하도록 합니다. 프롬프트 주입도 모델만의 문제로 보지 말고, 웹페이지나 파일에서 가져온 신뢰할 수 없는 지시와 실제 권한 요청을 구분해 기록합니다.

## 2. Apple의 Rosetta 지원 종료에 대비해 Intel 의존성을 확인한다

Apple은 macOS 26.4 이상에서 Rosetta가 필요한 앱을 실행하면 사용자에게 업데이트 안내가 표시될 수 있다고 공지했습니다. macOS 27은 Apple silicon에서 Intel 전용 앱을 실행할 수 있는 마지막 버전입니다. Apple은 개발자에게 유니버설 바이너리 배포를 권장했습니다. 앱 본체뿐 아니라 서드파티 프레임워크와 플러그인, 설치 도구, CI가 만든 보조 실행 파일에도 Intel 의존성이 남아 있는지 확인해야 합니다.

릴리스 후보마다 Apple silicon 기기에서 설치와 실행, 업데이트가 정상적으로 되는지 자동으로 확인합니다. `arm64`와 `x86_64` 빌드 결과를 살펴보고 Intel 전용 의존성이 남아 있다면 대체 버전과 담당자, 교체 기한을 기록합니다. 지원 종료를 늦게 준비하면 사용자는 앱을 실행할 수 없는 문제로 먼저 겪게 됩니다.

## 3. S3 PowerShell Drive: 익숙한 명령도 실제 객체를 삭제할 수 있다

AWS는 `AWS.Tools.S3` 5.0.288 이상에 S3 PowerShell Drive를 추가해 버킷과 객체를 PowerShell 세션 안에서 폴더와 파일처럼 탐색·읽기·쓰기·삭제할 수 있게 했습니다. AWS는 이것이 OS 수준의 마운트가 아니라 해당 PowerShell 세션 안에서만 존재하며, 기존 AWS 자격 증명과 리전 해석 방식을 따른다고 설명합니다. 즉, 탐색 작업은 간결해지지만 `Remove-Item` 같은 익숙한 파일 명령이 실제 객체 삭제로 이어질 수 있으므로 권한과 대상 확인의 중요성은 줄지 않습니다.

운영용 프로파일은 읽기 전용과 쓰기 가능으로 나누고, 쓰기 세션에서는 접근할 버킷과 경로, MFA, 세션 만료를 확인합니다. 먼저 운영에 쓰지 않는 버킷에서 경로 해석과 삭제 동작을 시험하고, 셸 기록이나 CloudTrail 로그로 변경을 추적할 수 있게 합니다. 편한 인터페이스를 쓰더라도 권한과 변경 내용을 확인하는 책임은 남습니다.
