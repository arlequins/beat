## 설정을 조합하는 방식이 달라진다

flat config는 배열과 `defineConfig`를 사용해 파일 패턴별 규칙을 조합합니다. 기존 `.eslintrc`의 상속과 무시 규칙에 익숙한 팀이라면 설정을 옮기는 데 그치지 말고, 파일마다 어떤 규칙이 적용되는지 다시 확인하고 문서화해야 합니다.

## TypeScript 모노레포에서의 순서

먼저 패키지별 `eslint.config.*`와 공통 프리셋의 역할을 나눕니다. 다음으로 TypeScript 파서와 React 규칙, 테스트 환경에서 쓰는 전역 변수를 파일 패턴에 맞춰 설정합니다. 마지막으로 CI에서 루트와 각 패키지의 검사 결과가 일치하는지 확인합니다.

## v10을 기다리지 말고 계약을 만든다

ESLint 10은 eslintrc 파일과 관련 명령줄 옵션을 제거할 계획입니다. 미리 설정을 옮기면 규칙이 빠지는 문제를 줄이고, 자체 플러그인이 폐기 예정 API에 의존하는지도 점검할 수 있습니다.
