이번 주의 공통점은 새 도구를 더 많이 쓰는 일이 아니라, 도구가 움직일 수 있는 범위를 코드와 정책으로 남기는 일입니다. 장시간 실행 에이전트, 이벤트로 시작되는 CI, 크기가 달라지는 화면은 모두 "작동한다"는 확인만으로는 부족합니다. 누가 무엇을 시작할 수 있고, 어디까지 접근하며, 어떤 조건에서 멈추는지를 배포 전에 정해야 합니다.

## 1. Agents API: 장시간 작업에는 실행 환경의 계약이 필요하다

OpenAI는 9월 10일 Codex 기반의 관리형 실행 구조를 제공하는 Agents API 공개 베타를 발표했습니다. 호스팅 샌드박스에서는 코드 실행·파일 작업·산출물 생성을 할 수 있고, 장시간 세션을 위한 컨텍스트 관리와 도구 검색·병렬 호출도 제공합니다. 이는 에이전트의 능력만 연결하는 일이 아니라, 파일·패키지·스킬·비밀값과 실행 시간을 어떤 환경 계약 안에 둘지 정하는 설계 문제입니다.

첫 배포에서는 읽기 전용 도구와 테스트 데이터로 시작하고, 작업별로 허용한 파일 경로·네트워크 대상·비밀값·최대 실행 시간·사람 승인 지점을 문서화합니다. 산출물과 도구 호출, 실패 원인을 작업 ID로 남겨야 재시도와 감사가 가능합니다. 베타 기능인 만큼 모델이나 런타임 변경이 결과에 미치는 영향도 회귀 평가로 계속 확인합니다.

출처: [OpenAI: Introducing the Agents API](https://openai.com/index/introducing-the-agents-api/), [OpenAI Developers: Agents API overview](https://developers.openai.com/api/docs/guides/agents)

## 2. GitHub Actions: 실행 전 보호 규칙을 평가 모드에서 검증하기

GitHub는 9월 17일 Actions 실행 보호 기능을 정식 출시했습니다. 이 기능은 워크플로를 시작할 수 있는 주체와 이벤트를 allowlist로 제어하며, 특정 워크플로 파일에만 다른 규칙을 적용하거나 REST API로 정책을 코드처럼 관리할 수 있습니다. 특히 공개 저장소의 `pull_request_target`에는 기본 차단 규칙이 도입되며, 영향은 먼저 평가 모드에서 확인한 뒤 11월 2일부터 해당 저장소에 적용될 예정입니다.

저장소별로 `pull_request_target` 사용 여부와 포크 PR에서 실행되는 코드 경로를 먼저 목록화합니다. 배포 워크플로처럼 비밀값에 닿는 파일에는 팀·이벤트별 허용 규칙을 적용하고, 평가 모드의 차단 예상 결과를 CI 실패와 구분해 검토합니다. 예외가 필요하면 전체 저장소를 푸는 대신 필요한 워크플로 파일과 이벤트만 명시적으로 허용합니다.

출처: [GitHub Changelog: Workflow execution protections in GitHub Actions](https://github.blog/changelog/2026-09-17-workflow-execution-protections-in-github-actions-generally-available/), [GitHub Docs: Control workflow execution](https://docs.github.com/actions/how-tos/manage-workflow-runs/control-workflow-execution)

## 3. iPhone Duo: 적응형 레이아웃을 출시 전 검증 항목으로 만들기

Apple은 9월 18일 iPhone Duo용 디자인 리소스와 전용 자료를 공개했고, 앱을 모든 화면 크기에 맞춰 최적화할 워크숍을 안내했습니다. 공식 준비 페이지는 Xcode 27.1 beta, 동적 리사이즈와 레이아웃 조정 문서, 여러 디스플레이와 장면을 다루는 자료를 함께 제공합니다. 접히는 기기는 화면 크기만 하나 추가되는 것이 아니라, 창 크기·방향·장면 전환 중에도 상태와 조작을 유지하는지를 묻습니다.

고정 폭·높이와 화면 좌표에 의존하는 뷰를 우선 찾아, 분할 화면과 크기 변경 중에도 목록 위치·입력 상태·진행 중 작업이 보존되는지 테스트합니다. SwiftUI와 UIKit 모두 동적 타입, 안전 영역, 키보드와 접근성 초점을 포함한 시나리오를 실제 베타 SDK와 시뮬레이터에서 실행합니다. 디자인 검토에는 펼친 상태의 스크린샷만 아니라 전환 직후의 상호작용도 포함합니다.

출처: [Apple Developer: Get ready for iPhone Duo](https://developer.apple.com/iphone-duo/), [Apple Developer News](https://developer.apple.com/news/)
