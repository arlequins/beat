> 2026-09-13 특별기획 · 공식 자료를 바탕으로 한 기술 해설

브라우저에서 요약이나 문장 교정을 처리하면 서버 호출을 줄일 수 있다. 하지만 사용자가 처음 확인하는 것은 모델의 답변이 아니라 자기 기기에서 기능을 쓸 수 있는지, 모델 준비에 얼마나 걸리는지다. 이 글에서는 데모 다음 단계인 첫 실행 화면을 어떻게 설계할지 살펴본다.

## API를 지원해도 바로 쓸 수 있는 것은 아니다

Chrome 공식 문서는 내장 AI 기능의 기기·언어·모델 조건과 준비 상태 확인을 안내한다. 모델 다운로드가 필요한 경우도 있고 지원하지 않는 환경도 있다. 따라서 모든 브라우저와 휴대전화에서 동일하게 동작하는 기능이라고 가정하면 안 된다.

먼저 기능을 탐지해야 한다. 제품은 사용 가능, 준비 중, 사용할 수 없음 상태를 나누어 보여줄 수 있다. 로딩 표시 하나로 이 차이를 감추면 사용자는 언제까지 기다려야 하는지 알기 어렵다. 구체적인 지원 버전은 도입 시점의 공식 API 문서에서 다시 확인해야 한다.

## 요약 버튼보다 먼저 필요한 선택

개인 메모 앱을 예로 들어 보자. 사용자가 긴 메모의 요약을 눌렀을 때 모델이 없으면 다운로드가 필요하다고 알려준다. 메모를 읽거나 고치는 기본 기능은 계속 사용할 수 있게 두는 편이 좋다. AI 준비가 끝날 때까지 앱 전체를 막을 이유는 없다.

로컬 처리가 안 된다는 이유로 내용을 자동으로 서버에 보내서는 안 된다. 기기 안에서 처리된다고 믿고 작성한 문장이 다른 곳으로 전달되면 사용자가 기대한 조건과 달라진다. 서버 처리로 전환하려면 어디로 어떤 내용이 전송되는지 설명하고 별도로 동의를 받아야 한다.

## 응답 속도 외에 측정할 것

첫 실행과 모델을 미리 준비한 실행, 저장 공간이 부족한 실행을 나누어 측정한다. 첫 결과가 나오기까지 걸리는 시간과 취소 후 원래 문서가 보존되는지도 확인한다. 개발자의 고성능 노트북에서 얻은 결과를 모든 사용자의 경험으로 일반화해서는 안 된다.

AI 기능 없이도 제품의 기본 기능을 쓸 수 있어야 한다. 요약을 만들 수 없는 상황에서도 메모를 찾고 읽을 수 있다면 AI는 기존 기능을 보완한다. 반대로 모델 준비에 실패했을 때 문서까지 열 수 없다면 편의 기능 하나가 앱 전체를 사용할 수 없게 된다.
