> 2026-09-13 특별기획 · 공식 자료를 바탕으로 한 기술 해설

브라우저 안에서 요약이나 문장 교정을 처리하면 서버 호출을 줄일 수 있다. 그러나 사용자가 처음 만나는 것은 모델의 답변이 아니라, 자기 기기에서 기능이 되는지와 얼마나 기다려야 하는지다. 2026년 9월 13일 특별기획 두 번째 글은 데모 이후의 첫 실행 화면을 다룬다.

## API가 있다는 사실과 준비됐다는 사실

Chrome 공식 문서는 내장 AI 기능의 기기·언어·모델 조건과 준비 상태 확인을 안내한다. 모델 다운로드가 필요한 경우도 있고 지원하지 않는 환경도 있다. 따라서 모든 브라우저와 휴대전화에서 동일하게 동작하는 기능이라고 가정하면 안 된다.

출발점은 기능 탐지다. 제품은 사용 가능, 준비 중, 지원하지 않음이라는 상태를 구분해 보여줄 수 있다. 로딩 표시 하나로 이 차이를 감추면 사용자는 기다림이 끝날지조차 알 수 없다. 구체적인 지원 버전은 도입 시점의 공식 API 문서를 다시 확인해야 한다.

## 요약 버튼보다 먼저 필요한 선택

개인 메모 앱을 예로 들어 보자. 사용자가 긴 메모의 요약을 눌렀을 때 모델이 없으면 다운로드가 필요하다고 알려준다. 메모를 읽거나 고치는 기본 기능은 계속 사용할 수 있게 두는 편이 좋다. AI 준비가 끝날 때까지 앱 전체를 막을 이유는 없다.

로컬 처리가 불가능하다고 내용을 자동으로 서버에 보내는 것도 피하고 싶다. 온디바이스라는 기대 아래 작성한 문장이 다른 곳으로 전달되면 사용자의 선택이 바뀐다. 서버 처리로 전환할 때에는 전송 대상과 내용을 설명하고 별도의 선택을 받는 흐름을 제안한다.

## 응답 속도 외에 측정할 것

첫 실행, 모델이 이미 준비된 실행, 저장 공간이 부족한 실행을 나누어 측정해 보자. 첫 유효 결과까지의 시간과 취소 후 원래 문서가 보존되는지를 함께 본다. 개발자의 고성능 노트북 한 대에서 나온 결과를 전체 사용자의 경험으로 일반화하지 않는다.

제품에서 AI를 뺀 상태도 사용 가능해야 한다. 요약을 못 만드는 날에도 메모를 찾고 읽을 수 있다면 기능은 점진적인 개선이 된다. 반대로 AI 준비 실패가 문서 접근 실패로 이어진다면 작은 편의 기능이 제품의 가용성을 지배하게 된다.
