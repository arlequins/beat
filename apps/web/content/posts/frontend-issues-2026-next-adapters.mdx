## 플랫폼이 읽을 수 있는 배포 규격

Next.js 16.2에서 Adapter API가 안정화되면서 라우트, 사전 렌더링 결과, 정적 자산, 실행 환경, 캐시 규칙을 플랫폼이 읽을 수 있는 버전이 명시된 형식으로 설명할 수 있게 됐습니다. 호스팅 업체가 프레임워크 내부 동작을 추측하지 않아도 됩니다.

## 플랫폼 독립성의 실제 비용

Adapter가 있다고 모든 배포가 동일해지는 것은 아닙니다. 스트리밍, 이미지, 캐시 무효화, 함수 실행 시간은 여전히 플랫폼마다 다릅니다. 배포 전에 adapter output과 실제 응답 헤더·캐시를 비교하는 계약 테스트가 필요합니다.

## 팀의 적용 순서

먼저 정적 경로와 서버 경로를 나누고, 각 배포 결과가 어떤 플랫폼 기능을 사용하는지 기록합니다. 그런 다음 같은 테스트 자료를 여러 어댑터에서 빌드해 라우팅과 캐시 동작을 비교합니다. 추상화는 차이를 감추기보다 확인하고 검증할 수 있게 해야 합니다.
