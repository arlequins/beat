## 브라우저와 서버 사이의 경계도 보안 대상이다

2025년 12월 공개된 React Server Components 취약점은 서버와 브라우저 사이에서 데이터를 주고받는 직렬화 프로토콜도 공격 대상이 될 수 있음을 보여줬습니다. 이를 단순히 “프런트엔드 의존성”으로만 분류하면 서버 런타임의 위험을 놓칠 수 있습니다.

## 패치 PR은 시작일 뿐이다

패키지를 업데이트한 뒤 잠금 파일(lockfile)과 빌드 결과물, 운영 중인 서버가 같은 버전을 사용하는지 확인해야 합니다. 취약한 경로를 실제로 쓰는지와 관계없이 공식 패치 버전으로 올리고, 캐시에 남은 이미지와 함수도 교체하는 것이 기본입니다.

## 다음 사고를 줄이는 목록

소프트웨어 구성 명세(SBOM)와 의존성 검토를 CI에 넣고 보안 릴리스 알림을 일반 기능 변경과 분리합니다. RSC나 서버 액션, 직렬화 경계를 사용하는 앱은 클라이언트 테스트만으로 충분하지 않습니다. 서버 요청의 오류 처리와 권한 검사도 회귀 테스트에 포함해야 합니다.
