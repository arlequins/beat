## 언어 기능보다 도구의 처리량

TypeScript 팀은 컴파일러와 언어 서비스를 네이티브 코드로 옮기는 작업을 공개했습니다. 대규모 프로젝트의 타입 검사와 편집기 응답을 빠르게 하는 것이 목표지만, 플러그인과 API의 호환성도 확인해야 합니다.

## 포팅은 팀의 빌드 계약을 흔든다

타입 검사기가 빨라져도 프로젝트 참조, 생성 코드, 선언 파일 출력, IDE 플러그인이 이전과 같은 결과를 내는지 확인해야 합니다. 도입 여부를 판단하려면 성능 향상 수치만 볼 것이 아니라 현재 저장소에서 시간이 오래 걸리는 작업부터 측정해야 합니다.

## 2025년에 할 준비

오래된 Compiler API 의존성을 찾고 `tsc`와 편집기 버전을 잠금 파일에 기록합니다. 야간 빌드나 네이티브 미리보기는 별도 CI 작업에서 시험하고, 결과가 다르면 기존 도구 체인으로 돌아갈 수 있게 합니다.
